Run with WebSearch and WebFetch. The ECC `deep-research` skill could not be used: it requires
firecrawl or exa MCP and neither is installed on this machine.

## The finding that matters: attribution data is arriving and being thrown away

Meta injects a click identifier, **`ctwa_clid`**, into the first inbound message of every
Click-to-WhatsApp conversation. It travels in the webhook `referral` object alongside `source_id`
(the ad ID). It is what ties a WhatsApp lead back to the exact ad, campaign, and audience that
produced it ([whapi.cloud](https://whapi.cloud/blog/track-click-to-whatsapp-ctwa-clid),
[metricfixer](https://metricfixer.com/publications/analytics-conversion-tracking/track-click-to-whatsapp-ads-campaign-ad-creative-without-website)).

**Kuanli already receives this webhook. It reads the `referral` object. It discards the identifiers.**

`automation_stack/wacrm/src/app/api/whatsapp/webhook/route.ts`:

- **Line 111** declares the type as
  `referral?: { headline?: string; body?: string; source_url?: string }`.
  `ctwa_clid` and `source_id` are not in the interface, so they are dropped at the type boundary even
  though Meta sends them.
- **Lines 988 to 999** use the three surviving fields to render a display banner
  (`🚀 *Ad Clicked:* ...`) prepended to the message text.
- Nothing persists any of it. `grep -n referral route.ts` returns those two blocks and nothing else.

So on every click-to-WhatsApp ad, the exact data needed to connect spend to admissions arrives, gets
turned into a cosmetic banner, and is lost.

### Why this reframes the measurement work

The plan assumed WhatsApp attribution had to be designed from scratch. It does not. The pieces are:

1. **Capture.** Extend the interface at line 111 to include `ctwa_clid` and `source_id`, and persist
   both against the contact on first inbound message. This is a small, contained change.
2. **Store.** Keep them on the Kuanli contact record so they survive to the admission event.
3. **Report.** Fire Conversions API events with `action_source: "business_messaging"` and
   `"messaging_channel": "whatsapp"`, carrying the original `ctwa_clid`. Both fields are required;
   without them Meta does not recognise the conversion as coming from a CTWA ad
   ([Aixel](https://aixel.io/blog/whatsapp-conversions-api),
   [WOZTELL](https://support.woztell.com/portal/en/kb/articles/wa-conversion-flow)).

This is the difference between "cost per conversation started" and actual cost per admission, which
is the metric the whole quarter is judged on.

**Caveat:** whether Meta currently sends `ctwa_clid` on this WABA's webhooks has not been verified.
The fix is to log the raw `referral` payload on the next inbound ad-sourced message and read what is
actually in it, before building anything on the assumption.

**Corroboration:** the openclaw project has an open issue requesting exactly this field be exposed
in session metadata ([issue #39037](https://github.com/openclaw/openclaw/issues/39037)), which
confirms the field is real and that dropping it is a common mistake, not a local one.

## Tooling worth adopting

### Recommended: `thatrebeccarae/claude-marketing`

MIT, 114 stars, 126 commits. Skill packs for Claude Code.

The **Paid Media Pack** is directly on-target: a Meta Ads skill offering scored account audits (46
checks, A-F health grade), creative fatigue diagnosis, **pixel/CAPI health**, and iOS 14.5+
attribution; plus a **Wasted Spend Finder** covering Google and Meta, and an Account Structure Review
for budget fragmentation and consolidation.

That waste-finding work is exactly the analysis done by hand on the LPU account. Having it as a
repeatable scored audit is worth more than the one-off.

Install by cloning and copying only the Paid Media Pack skill folders. It ships Python setup wizards;
those are not needed for the Meta skills and should be skipped. Analysis runs in-memory with output
to local files. The Klaviyo, Shopify, GA4, and Looker credentials it mentions belong to other packs
and are not required for Meta.

### Recommended, selectively: `OpenClaudia/openclaudia-skills`

MIT, 656 stars, 47 forks, last updated 2026-08-17. 34+ marketing skills.

Relevant to this workspace: `facebook-ads`, `page-cro`, `ab-test-setup`, `video-ad-analysis`, and on
the organic side `seo-audit`, `keyword-research`, `schema-markup`, `search-console`,
`gsc-portfolio-audit`, `content-gap-analysis`.

Star-to-fork ratio is healthy and the activity is recent, so no anomaly of the kind flagged on
`graphify` in the 2026-08-03 review.

**Do not run `npx openclaudia install --all`.** Copy the four or five wanted skills manually into
`.claude/skills/`, which is the same approach taken with Emil Kowalski's skills on 2026-08-12 and for
the same reason: the payload is markdown, so there is no reason to introduce an unvetted CLI to move
it. Many of its skills also expect third-party API keys (SemRush, Ahrefs, DataForSEO, SerpAPI,
Apollo) and send data to those services when configured. Take only the local-only ones.

## Recommended order

1. **Log the raw `referral` payload** on the next ad-sourced inbound message. Confirms whether
   `ctwa_clid` is actually present before anything is built on it. Cheapest possible step.
2. **Capture and persist `ctwa_clid` + `source_id`** in the Kuanli webhook handler.
3. **Wire CAPI for business messaging** with the two required fields.
4. Adopt the `claude-marketing` Paid Media Pack for repeatable scored audits.
5. Cherry-pick the OpenClaudia SEO skills when Phase 3 starts.

Steps 2 and 3 touch production code handling student PII and belong behind the `dev-team` four-lens
review already specified in `CLAUDE.md`, and arguably `santa-method` as well.
